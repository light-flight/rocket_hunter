# Rocket Hunter

PWA для менеджера картинговой команды: помогает отслеживать, какая машина стоит на выходе
из пит-коридора. Работает без сети и синхронизируется с сервером, когда связь появляется.

Сейчас в репозитории каркас и вход: менеджеры входят через бота в Telegram, новые попадают
в команду только по приглашению. После входа — экран-заглушка с проверкой связи и готовности
к работе без сети.

## Устройство

- **Сервер** — Rails 8.1 + PostgreSQL. Отдаёт JSON под `/api` и принимает сообщения бота
  на `/telegram/webhook`.
- **Клиент** — React + TypeScript + Vite в `frontend/`. Сборка копируется в `public/`,
  и Rails раздаёт её как статические файлы с корня сайта. Статические файлы сайта кладутся
  в `frontend/public/`: каталог `public/` очищается при каждой сборке, в нём сохраняются
  только файлы Rails, перечисленные в `.gitignore`.
- **Офлайн** — `vite-plugin-pwa` кэширует приложение на телефоне, данные лежат в IndexedDB (Dexie).
- **Вход** — только через Telegram, без паролей и почты. Приложение даёт ссылку на бота,
  менеджер нажимает в боте «Запустить» и «Войти», возвращается в приложение, и оно входит само.
  Сервер к Telegram не обращается: ответ бота уходит в теле ответа на webhook.
  Потерянная сессия работать не мешает: приложение остаётся на экране и просит войти снова.

## Запуск

Нужны [mise](https://mise.jdx.dev) (версии Ruby и Node в `mise.toml`) и Docker.

```bash
mise install
bin/setup
```

`bin/setup` ставит зависимости, поднимает PostgreSQL из `compose.yaml` (порт 5433),
создаёт базы и запускает `bin/dev`: Rails на порту 3000 и Vite на 5173.
Приложение при разработке открывается по адресу http://localhost:5173.
Если mise не активирован в оболочке, запускайте команды через `mise exec -- ...`.

В режиме разработки service worker выключен. Чтобы проверить работу без сети,
соберите приложение в `public/` и откройте его через Rails по адресу http://localhost:3000:

```bash
npm --prefix frontend run build:rails
```

### Вход при разработке

Бот для этого не нужен. Нажмите «Войти через Telegram» на http://localhost:5173 (откроется
вкладка Telegram — её можно закрыть) и подтвердите вход в консоли (`bin/rails console`),
приложение войдёт само:

```ruby
SignInAttempt.last.update!(user: User.find_or_create_by!(telegram_id: 1) { |u| u.name = "Разработчик" })
```

Чтобы пройти тот же путь, что и с ботом, отправьте серверу два сообщения от имени Telegram.
Менеджер с `telegram_id: 1` должен уже существовать (его создаёт команда выше), `TOKEN` —
часть ссылки «Войти через Telegram» после `start=`:

```bash
TOKEN=...
curl localhost:3000/telegram/webhook \
  -H 'Content-Type: application/json' -H 'X-Telegram-Bot-Api-Secret-Token: development' \
  -d '{"message":{"from":{"id":1},"chat":{"id":1,"type":"private"},"text":"/start '"$TOKEN"'"}}'
curl localhost:3000/telegram/webhook \
  -H 'Content-Type: application/json' -H 'X-Telegram-Bot-Api-Secret-Token: development' \
  -d '{"callback_query":{"id":"1","from":{"id":1},"data":"confirm:'"$TOKEN"'"}}'
```

Первый запрос — менеджер открыл бота по ссылке (в ответе вопрос с кнопками), второй — нажал «Войти».

## Бот в Telegram

Без бота на выложенном сервере не войти. Настраивается один раз:

1. У [@BotFather](https://t.me/BotFather): `/newbot` — название и username бота, затем
   `/setjoingroups` → Disable, чтобы бота нельзя было добавить в группу.
2. Username бота записать в `config.x.telegram.bot_username` в `config/application.rb`
   (это не секрет: он виден в каждой ссылке).
3. Токен бота и секрет webhook положить в credentials (`bin/rails credentials:edit`):

   ```yaml
   telegram:
     bot_token: "123456:ABC..."   # выдаёт BotFather
     webhook_secret: "..."        # своя случайная строка, например вывод bin/rails secret
   ```

   Пока секрета нет, `/telegram/webhook` отвечает 403 на любой запрос.
4. Выложить и сообщить Telegram, куда присылать сообщения бота:

   ```bash
   bin/kamal deploy
   bin/kamal app exec --reuse 'bin/rails telegram:set_webhook'
   bin/kamal app exec --reuse 'bin/rails telegram:webhook_info'   # проверить адрес и последнюю ошибку доставки
   ```

Токен бота нужен только этим двум задачам; само приложение к Telegram не обращается.

## Учётные записи

Менеджер попадает в команду по приглашению: вошедший менеджер нажимает «Пригласить менеджера»
и отправляет ссылку. Ссылка одноразовая и действует 3 дня. Всё остальное делается в консоли
(`bin/kamal console`):

```ruby
puts Invitation.create!.url             # первая учётная запись или приглашение, когда войти не может никто
User.order(:created_at).pluck(:id, :name, :username, :telegram_id, :invited_by_id, :created_at)
User.find(ID).sessions.destroy_all      # потерян телефон
User.where(invited_by_id: ID)           # кого он пригласил; посмотреть до удаления: после него эта связь стирается
User.find(ID).destroy!                  # убрать менеджера: его сессии и неиспользованные ссылки тоже удаляются
Invitation.delete_all                   # отменить все выданные ссылки
Session.delete_all                      # все входят заново (нужно и после восстановления базы из копии)
```

Что важно помнить:

- **Чужой человек получил доступ к Telegram менеджера** — сначала посмотреть, кого этот
  менеджер пригласил (`User.where(invited_by_id: ID)`), и убрать незнакомых, затем
  `User.find(ID).destroy!`.
- **Утёк токен бота** — у BotFather `/revoke`, новый токен в credentials, выкладка,
  `telegram:set_webhook`, `Invitation.delete_all`.
- **Секрет webhook** так же важен, как `secret_key_base`: кто его знает, может подделать
  сообщения бота и войти под любым менеджером. При утечке — новый секрет в credentials,
  выкладка, `telegram:set_webhook`.
- **Никогда не включать `RAILS_LOG_LEVEL=debug` на сервере**: в таком журнале видны токены
  входа и приглашений.
- Когда по приглашению кто-то вошёл, об этом никому не сообщается: новых людей видно только
  в списке `User`.
- Удалённый менеджер войти больше не может, но то, что уже записано на его телефоне,
  там остаётся.

## Проверка на телефоне

Нужен выложенный сервер с HTTPS и настроенный бот: без HTTPS service worker на телефоне не работает.

1. Открыть адрес приложения в браузере (iPhone — Safari или Chrome, Android — Chrome, не
   внутри Telegram) и добавить на экран «Домой».
2. Открыть приложение **с иконки при наличии сети**, нажать «Войти через Telegram» — откроется
   Telegram. В боте нажать «Запустить» и «Войти», вернуться в приложение: вход
   выполняется сам, в строке «Менеджер» появляется имя.
   На iPhone у приложения с иконки своё хранилище, отдельное от Safari: вход, выполненный
   во вкладке Safari, в него не переходит.
3. Дождаться «Работа без сети: готово», включить авиарежим, закрыть приложение и открыть снова:
   приложение открывается, имя менеджера на месте, войти заново не просят.
4. Перезагрузить телефон, открыть приложение без сети: то же самое.
5. Вернуть сеть, нажать «Пригласить менеджера» и «Поделиться»: текст со ссылкой уходит
   в Telegram. Второй человек открывает ссылку, нажимает «Запустить», получает инструкцию
   и входит на своём телефоне.
6. Нажать «Выйти»: появляется экран входа. Без сети выйти нельзя, приложение об этом говорит.
7. Выложить новую сборку, вернуться в открытое приложение: появляется кнопка обновления,
   после нажатия строка «Сборка» внизу меняется.

## Проверки

```bash
bin/ci
```

Запускает RuboCop, Brakeman, тесты Rails, линтер клиента и сценарий Playwright. Сценарий
открывает собранное приложение через Rails, входит так, как это происходит с ботом
(сообщения Telegram отправляются на настоящий webhook с тестовым секретом), отключает сеть
и проверяет, что приложение открывается и менеджер остаётся в нём, а потом проверяет
повторный вход после потери сессии и выход.
